# 进益资本杯 2026 端到端赛道三人分工报告

版本：2026 年 10 月 8 日。适用对象：三名具备 AI 基础的队员。A、B、C 为角色代号，分配姓名后即可执行。具体数据字段、标签和评测口径以官方模板为准。

## 一、项目目标与分工原则

模型读取股票截至决策时点可见的历史分钟行情及盘口数据，输出预测未来 30 分钟 VWAP 收益的分数。分数越高，预期收益越高。训练阶段学习模型参数，平台评测阶段加载已训练参数进行推理。

以 IC、IC_IR、多空组合夏普、压力场景稳定性与换手表现指导模型选择。现有赛事说明未给出最终评分权重，须核对官方评估实现。

分工遵循三项原则：三人从第一天就有独立任务；各自承担研究与工程工作；通过共同接口和持续集成保证最终可对接。

## 二、职责总览

| 角色 | 核心问题 | 技术责任 | 研究责任 |
| --- | --- | --- | --- |
| A：数据与输入编码 | 原始数值如何变成模型能学习的表示？ | 数据管线、历史窗口、标准化、掩码、InputEncoder | 字段分组、盘口结构、分钟与 patch token |
| B：时序模型与训练执行 | 历史 token 的关系如何变成预测分数？ | 时序主干、池化、预测头、联合训练、检查点 | GRU、Transformer、时序卷积与历史汇总方式 |
| C：训练目标与比赛评估 | 怎样训练并判断模型是否提高比赛表现？ | 损失函数、指标报告、官方评估适配、平台 Notebook | 回归与排序目标、稳定性、换手约束 |

计算链：原始历史窗口 → A 的 encoder → B 的主干与预测头 → score → C 的损失或评估。B 的训练程序连接三人的模块，梯度同时更新 A 和 B 的模型参数。

## 三、A 的任务清单

### 从第一天开始

1. 编写字段配置和模拟历史窗口，输出数值及观测掩码。
2. 实现分组 MLP encoder，分别编码价格、成交、盘口等输入组，再融合成 token。
3. 明确缺失值、左侧填充与全缺失窗口处理。
4. 整理字段、单位、时间语义和官方标签的待确认问题。

### 数据到达后

接通真实数据；确认记录可见时间、交易时段与历史股票池；构建合法窗口和同一决策时点的股票批次；仅用训练区间拟合标准化状态。A 实现标签数据构建，C 共同核对公式及时间边界。

### 交付与研究

交付数据适配器、窗口构建器、可保存的预处理器、可训练 encoder 和字段说明。第一项研究比较分组编码与简单统一编码；第二项可比较分钟 token 与学习式 patch token。每次固定 B 的主干和 C 的目标后比较。

## 四、B 的任务清单：具体到模块

B 接收每只股票的一段历史 token。其工作是学习历史片段之间的联系，将历史压缩为表示，再输出一个标量分数。

| 模块 | 输入 → 输出 | 第一版实现 | 明确交付物 |
| --- | --- | --- | --- |
| 时序主干 | `[B,N,D]` → 隐藏状态序列 | 小型 GRU，处理有效长度 | `backbone` 模块 |
| 历史汇总 | 隐藏状态序列 → `[B,H]` | 最后有效时刻的隐藏状态 | `pooling` 模块 |
| 预测头 | `[B,H]` → `[B]` | 两层 MLP | `head` 模块 |
| 训练执行 | A 的 batch + A/B 模型 + C 的 loss → 参数更新 | 优化器、梯度裁剪、日志、验证和早停 | 训练入口 |
| 保存与加载 | 模型及处理状态 → 可重现预测 | 完整检查点和加载函数 | 检查点接口 |

第一版数学过程：`h_k = GRU(z_k, h_(k-1))`，`score = MLP(h_最后有效时刻)`。B 负责 token 的时序关系，A 负责 token 本身的构造。

### 从第一天开始

1. 按约定形状自己生成模拟 token，直接开发 GRU、池化和预测头。
2. 用演示线性 encoder 和简单演示损失接通最小训练程序，预留 A、C 模块接口。
3. 实现保存、加载、设备转移和梯度裁剪。
4. A、C 模块就绪后替换演示模块；优化器必须包含 encoder 的参数。

### 数据到达后与研究

接入真实 batch，完成训练、恢复与预测。记录显存、内存、耗时和批次规模。第一项研究用 patch Transformer 替换 GRU，保持 A 的输入处理、C 的目标和验证切分一致；之后再比较历史长度或池化方法。

Transformer 实验中，A 负责生成 patch token，B 负责位置编码、注意力主干与池化。修改 token 顺序或轴语义时双方先共同更新接口。

## 五、C 的任务清单

### 从第一天开始

1. 实现 Huber 回归损失与同一截面内的排序损失。
2. 自己构造 score、收益标签、决策时点和股票标识，形成指标与报告样例。
3. 整理 IC、IC_IR、夏普、压力场景和换手的计算假设，列出官方待确认项。
4. 定义实验记录和模型选择规则，编写平台推理入口的调用流程草稿。

C 的第一阶段已经参与训练目标设计。人工构造数据可用于检查同向、反向、并列、常数与缺失情况；常数截面的相关系数不可定义，应按记录的规则处理。

### 数据到达后与研究

核对标签与官方评估模块；接通研究报告和官方报告；比较 Huber 与 Huber + 截面排序损失；研究稳定性和换手约束。换手计算须在连续时点对齐持仓和股票，不能直接比较不同 batch 的分数。

交付 objective、研究评估器、实验报告、官方评估适配和唯一推理 Notebook。Notebook 调用 A 的处理器和 B 的加载入口，不能另写一套预处理。输出字段及合法时点按端到端官方预测模板确认。

## 六、共同接口与责任边界

以下是目标接口，需与现有原型逐步对齐；不代表已全部实现。

| 边界 | 合同 |
| --- | --- |
| 数据 → A | `x: float32 [B,L,F]`，`observed: bool [B,L,F]` |
| A → B | `tokens: float32 [B,N,D]`，`token_valid: bool [B,N]` |
| B → C | `scores: float32 [B]`，保持原始样本顺序 |
| 训练损失 | `objective(scores, target, decision_id)` |
| 完整推理 | `model(x, observed) -> scores`；不接收未来标签 |

B 是样本数，L 是历史分钟数，F 是字段数，N 是 token 数，D 是 token 维度。所有外部掩码统一 True=有效。字段顺序、token 顺序、padding、标准化状态与配置共同保存。模型输入只包含决策时点已知信息。

A 提供时间与股票元数据，C 按 `decision_id` 构造截面损失，B 负责数据转移和训练调用。训练切分按时间确定，A 与 C 检查标签结束时间没有越过验证边界。

检查点由 B 保存，A 提供预处理状态，C 提供评分与选择记录。默认不缓存学习后的 token，避免冻结 encoder。任何接口变化由三人共同确认。

## 七、前三天并行安排

以团队启动日为第 1 天，不依赖数据是否发放。

| 阶段 | A | B | C | 共同交付 |
| --- | --- | --- | --- | --- |
| 第 1 天 | 模拟窗口、掩码、encoder | 模拟 token、GRU、预测头 | 模拟分数、loss、指标样例 | 模块接口可调用 |
| 第 2 天 | 预处理状态、异常输入策略 | 接通训练、保存加载 | 接通报告、切分规则 | 首次三模块拼接 |
| 第 3 天 | 修复输入与编码问题 | 完成联合训练与加载 | 输出报告与提交检查项 | 工程闭环、各一张研究计划卡 |

开始前共同用约 45 分钟确认接口、环境和代码边界。模拟数据只用于工程对接，不用于判断金融预测效果。

数据到达后，争取用 2 至 3 天完成短区间的真实数据闭环。时间取决于数据口径和访问情况；先解决口径，再扩大训练规模。

## 八、协作与工作量平衡

- 每人同时推进一个工程任务和一个研究实验；每项任务拆成约半天到一天的可交付单元。
- 每天安排约 20 分钟对接，报告完成项、接口变化、阻塞和下一交付；进行一次小规模集成。
- 集成主持人轮换。错误由所属模块负责人修复，平台报错由 C 定位并分派。
- A 前期偏重数据，后期转向编码消融；B 中期偏重训练，长训练期间推进推理性能；C 从初期设计损失，后期偏重官方评估与提交。
- 每周比较剩余任务与实际耗时。单人连续阻塞或超量时，由任务较轻者接走独立任务，并明确新的负责人。
- 文件分工：A 负责数据、预处理与 encoder；B 负责主干、模型组装和训练；C 负责 loss、指标和提交。现有 `model.py` 中两类模块应先划清文件边界。
- 交叉审阅：C 审 A 的时间与标签，A 审 B 的梯度和完整检查点，B 审 C 的指标与推理调用。

## 九、实验与最终验收

统一基线采用单频历史输入、分组 MLP encoder、小型 GRU 和 Huber 损失。候选 L=120、D=64 是初值，实际按数据及资源调整。固定时间切分和评估口径，每次主要修改一个因素。

每项实验记录：模块版本、配置、种子、切分、覆盖率、检查点、五类比赛指标、耗时及相对基线变化。训练 loss 用于诊断，模型保留依据样本外比赛表现。研究指标不能自动等同官方分数。

共同验收要求：无未来数据；标签边界合规；encoder 与主干联合训练；加载后可重现推理；输出符合官方合同；提交包含一个 Notebook 和完整依赖、配置、脚本、种子及权重；无需外网并满足三小时运行上限。
